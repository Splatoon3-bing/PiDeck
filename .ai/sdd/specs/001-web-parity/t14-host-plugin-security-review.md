# T14 宿主插件（只读）— 安全评审（v1 结论：实现后置）

> Scope: FR-020 / design §4.9。评审先于代码。

## 1. 现状核查

- 宿主插件是 PiDeck 原生能力（`src/main/plugins/`）：manifest 权限、内容 sha256 授权、私有 storage、webview 面板、`service.local` 点名权。
- 桌面授权 UI 明确提示「会话读取 + 联网」的数据外发风险；授权按内容指纹，指纹变化即失效。

## 2. 威胁模型（若向 Web 开放）

| 威胁 | 影响 | 说明 |
|---|---|---|
| Web 触发安装/更新/执行 | 高：等于把「装代码 + 跑服务」的权限交给任何拿到 token 的浏览器 | 必须保持关闭 |
| Web 读取插件清单携带路径 | 中：泄露宿主目录结构、账号标识 | 只读投影也必须剥离路径/指纹原文 |
| Web 授权（grant） | 高：绕过桌面「知情授权」语义 | 不得提供 |
| 插件私有 storage 读写 | 中：跨插件数据、凭据 | 不开放 |

## 3. v1 决定

- **不开放任何宿主插件路由**：不新增 `/api/host-plugins`，Web 端不出现入口。
- 理由：T14 是 Could Have；只读清单对日常使用价值有限，却需要一套新的投影/脱敏与授权语义评审；当前优先级低于全量测试红单与 T12 收口。
- 若未来要做，最小安全切片：`GET /api/host-plugins` 只返回 `{id, name, version, enabled, permissions: string[]}`（不含路径/指纹/storage），不提供安装、授权、执行、面板打开；并补 3 条拒绝用例（未知字段、非只读方法、未授权指纹）。

## 4. 与既有纪律的关系

- 不新增 pi↔PiDeck 通道；不改 `docs/host-plugin-dev-guide.md` 的 API 面（本任务零 API 变更）。
- 评审结论记录在此，避免后续会话误以为「漏做」。
